# Project-grounded explanations

Use `$tequio-explain` for an optional lesson: “Explain this backend decision,” “Teach me enough about load balancing to judge whether we need it,” or “Explain deployment for this project, assuming I am new to operations.” It is not a fifth development phase. `$tequio-learn` retains its existing job of codifying demonstrated findings into maintained guidance.

Explain reads the minimum relevant current context, distinguishes implementation from accepted/proposed/hypothetical designs and challenges unsupported complexity. With no topic, it infers only an unambiguous immediate subject or asks one short question. Broad topics become a bounded project-relevant map. Optional depth and predict–observe–explain–transfer activities support learning; no quiz blocks development and no score guarantees mastery.

The default deliverable is a self-contained offline HTML lesson with semantic text, useful diagrams and bounded local interactions. Controls must change an explicit model, not decorate an infographic. The portable example illustrates deterministic synthetic routing with finite queues, capacities and drops; it is not a production simulator, live metric or vendor guarantee. A backend decision can instead use a causal storyboard. Static worked examples, native optional depth, keyboard/focus/touch controls, narrow layout, reduced motion, pause/step/reset and print/no-script reasoning keep the core useful across capabilities. Actual rendering gaps must be stated.

Animated lessons should unfold as visual explanations: establish a state, follow an event, show its consequence and compare a changed condition. Objects and labels stay connected through the sequence, with pause/replay and meaningful learner control. The example's routing model is illustrative; other topics need their own appropriate visual structure. Moving dots or reveal buttons alone do not establish visual quality. Authors inspect complete motion as well as static screenshots, and state any untested rendering limits.

## Where the lesson lives

Preparation is temporary first. Once it is ready, Explain asks where to keep it, with contextual examples and free choice. A destination already explicitly supplied is reused; no repetitive question is needed. There is no required repository copy or workspace/database ceremony. After authorization, delivery uses a fresh collision-safe path, complete-byte/asset/link verification and staging-only cleanup. Existing files and unexpected symlinks are protected. Failed transfer preserves source; uncertain cleanup is reported as a remaining duplicate. Unsupported remote destinations are not silently redirected or published.

A named vault folder can be the sole retained home. An optional Markdown summary and relative HTML link aid discovery. Obsidian storage does not imply JavaScript executes inside its note view; use the standalone HTML in a normal browser. Actual Obsidian desktop/mobile opening must be distinguished from a synthetic vault-style storage/browser check. Explain never installs plugins or weakens viewer security. Local ignore rules, backup/sync and host/provider handling are not universal secrecy guarantees.

## Safety and qualification limits

Source excerpts are inert escaped data. Lessons have no remote dependencies, telemetry, file/API access, operational commands, learner-code execution or automatic network traffic. Deliberate primary-source links remain ordinary links. Restrictive CSP is defense in depth, not a complete sandbox. Review generated scripts/data as well as content. Teaching does not authorize code/config/spec/task mutation, application execution, installs, spending, deployment or publication.

Distribution/model tests can establish asset integrity and finite-model invariants. They cannot establish agent compliance, conceptual mastery, actual reviewer independence or universal browser/vault behavior. Feature qualification must inspect an actual generated project-grounded lesson, real rendered controls and teaching reasoning; record unavailable capabilities as pending. The bounded internal `tests/explain_artifact_probe.py --manifest <private-manifest>` validates evidence paths/hashes and explicit observations/gaps. It does not generate observations or certify their truth. Do not close required qualification by feeding it an unobserved all-true report.
