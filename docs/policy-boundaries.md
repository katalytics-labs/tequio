# Policy proof without unnecessary functional requalification

Freshness follows the declared dependency boundary, not filenames. A change to `.gitignore` can invalidate privacy proof. It should also invalidate functional proof when that proof actually depends on it. There is no file-type exemption, semantic-equivalence approval or cached-PASS override.

For new explicitly scoped work, give functional code, interfaces and runtime configuration their actual producer/read boundaries. Give installation/export/privacy rules a separate owner and real checks against current bytes. Join both prerequisites at final integration. Do not declare independence if a functional task reads the policy, a parent directory containing it, or another policy-dependent producer. Shared semantic documentation and runtime dependencies remain functional inputs.

## Reproducible policy successor

Run `python3 -m unittest discover -s tests -p test_policy_boundaries.py -v`. The temporary synthetic project:

1. Executes functional and consumer checks, docs and fixture review gates. A separate policy task checks exact current bytes and required private-path protections.
2. Changes policy bytes. Policy proof becomes noncurrent and integration refuses; independent functional/consumer definitions, receipt bytes and current proof remain unchanged.
3. Imports a separately reviewed new policy successor normally, then applies a reviewed rebind-only revision to the unfinished integration consumer. The completed old policy task is never rewritten or superseded.
4. Demonstrates a changed-after-claim policy failing real verification, then executes the successor against the intended current bytes and obtains its current checks, docs and both required fixture reviews before integration completes.

A matching byte digest alone is insufficient: a negative fixture with required private-path protections absent fails. Other controls change source, shared runtime configuration and semantic interface docs; affected functional proof becomes stale. Direct policy readers, policy dependencies, overlapping parent resources and mixed scoped/global histories stay conservative. These are controlled local assertions, not universal Git privacy or semantic review certification. Synthetic actor labels test gate mechanics, not actual independent identities.

## Measured roadmap refinement

Run `python3 -m unittest discover -s tests -p test_proportional_flow.py -v`. On three two-task unfinished branches plus an independent completed control:

| Actual engine trace | Broad replan | Explicit scoped revision |
|---|---:|---:|
| Old unfinished IDs superseded | 6 | 1 |
| New definitions authored/imported | 7 | 2 |
| Refinement operations after common setup | 7 | 4 |

Broad operations are replan, two phase records, task preparation, two review publications and import. Revision operations are prepare, two review publications and apply. Both retain required reviews. The scoped trace explicitly rebinds one unchanged consumer and preserves the other branch rows and completed control proof; unchanged consumer identity does not preserve old acceptance after a binding change. Historical-consumer refusal and stale-old-proof controls also run in the revision tests. This measures reproducible administrative churn, not tokens, billing, model performance or elapsed-product speedup.

## Deliberate migration and rollout

Existing global or mixed functional/policy producers remain conservative. Do not repair their successful receipts, infer a harmless ignore edit or retrofit their immutable definitions. Introduce new reviewed scoped successors, execute current checks/docs/reviews, and explicitly rebind only unfinished consumers. Requirements or source changes still require current analysis/plan approvals. See [revision](revision.md) for exact commands and historical boundaries.

Before any separately authorized target rollout, back up its controller/workspace and inspect actual owners, source/installed versions and `doctor --source PATH` observations. Resolve modified-owned files through normal installer refusals. Upgrade the executing controller before applying overlays; an old runtime cannot interpret them and downgrade is unsupported. Start a fresh host session for updated skill discovery. Confirm all private runtime/discovery/evidence paths remain ignored, including any new skills; ignore rules do not remove already tracked content or sanitize history. Repository-local exclude is clone-local, not a universal installer design. Source qualification does not authorize installation into another project, public export or publication.
