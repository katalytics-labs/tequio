# Portable teaching artifact contract

## Authoring interface

`../templates/lesson.html` is a complete synthetic routing lesson and reusable semantic/layout/control example. Adapt trusted HTML sections directly; no arbitrary JSON-to-HTML renderer or generator service is included. A usable generated artifact supplies title/topic, objective, assumptions, current/proposed/hypothetical status, dated/versioned project evidence, concept overview, worked example, visual description, alternative/tradeoff, misconception feedback, transfer challenge with reasoning, limitations and next step. Empty slots/comments do not satisfy these fields. Backend alternative: show request → validation → transaction → response, compare a proposed queue against a synchronous transaction using two worked state snapshots, predict failure before commit, then transfer to duplicate delivery. A second simulation engine is unnecessary.

Untrusted excerpts become escaped text nodes (`&`, `<`, `>`, quotes escaped where appropriate); never execute Markdown HTML, scripts or template expressions. Dynamic content uses textContent. If JSON must live in HTML, serialize it as data and escape `<` as `\u003c`, `>` as `\u003e` and `&` as `\u0026` before insertion, including script terminators; parse with JSON.parse, never eval. Do not embed secrets even when escaped. Source links are deliberate http/https links or safe relative references. No remote image/font/script, forms, frames, file/API/credential access, imports, telemetry or arbitrary code execution. CSP blocks remote connections/embeds but is not a complete sandbox; audit actual code as well.

## Motion and visual direction

Storyboard a short explanatory sequence before implementation: establish the objects, follow a concrete event, reveal its consequence, then contrast a changed condition. Prefer an integrated scene where travel, waiting, processing and outcomes share a spatial grammar. Use consistent object identities, intentional easing, staggered arrivals and focal emphasis to make causality legible. Short annotations should appear where the consequence occurs. Avoid disconnected diagrams and counters that require the reader to mentally reconcile two versions of the same system.

Make an authored guided path available alongside model controls when it helps novices: for example, follow one request, create overload, then remove a server. Guided presets must operate the same finite model as free exploration and disclose whether they reset or advance it. They are demonstrations, not measurements or alternate hidden calculations. Preserve step/replay and settled state; pause and reduced motion must not strand the lesson between contradictory states.

Visual review observes a whole sequence at ordinary speed plus a narrow-screen view, not merely DOM assertions or an attractive still. Judge hierarchy, readable labels, motion continuity, purposeful timing and whether the change is understandable without reading a wall of prose. A decorative particle layer, perpetual glow, card fades or a slideshow of hidden paragraphs is insufficient when an animated explanation was requested. Avoid a universal aesthetic score or mastery claim. A simple storyboard remains appropriate for a topic that does not benefit from simulation; disclose static limitations when animated rendering is unavailable.

## Shipped finite example behavior

The `routing-model` script is the actual pure model used by controls. It exports `createRoutingModel` under Node for direct invariant tests. Three independent servers; integer arrivals 0–12, capacity 1–4 per enabled server per tick, per-server queue bound eight. Each tick first applies changed inputs and drops disabled queues, then assigns arrivals round robin over enabled servers. Full chosen destinations drop; there is no reroute. The pointer advances after each assignment. Then enabled servers process min(capacity, queued). All disabled means all arrivals drop. Reenable starts empty. Counts obey arrivals = completed + dropped + queued. Model snapshots are copied so callers cannot mutate internals.

Changes take effect at discrete boundaries, not mid-animation. Step performs exactly one full boundary; Play paces ticks every 3.6 seconds and never measures throughput. Pause and hidden tabs stop progression and settle transient replay queues to the committed model state. At 120 ticks controls pause until reset. Reset restores load3/capacity2/all enabled/empty queues/totals/pointer0, paused. Nonfinite inputs use defaults; finite out-of-range/fractional inputs clamp/truncate to documented integers with visible feedback. The animation marks the resulting waiting state after accepted/processed counts are explained; it does not claim real packet timings or animate completed requests as waiting ones. System/manual reduced motion remove movement without losing state.

Deterministic example, not a production simulation: no random arrivals, health checks, retry timing, distributed consistency, shared database or real traffic measurements. A real project may use a different queue location/routing algorithm; label that difference. Primary references for adapted real-world claims should be current and specific; e.g. AWS ELB overview describes health-based routing, which is absent here. MDN's Content Security Policy guidance explains meta-delivered limitations; do not claim CSP authenticates or isolates arbitrary hostile generated lessons.

## Inspection and delivery

Read and test actual generated output, not only the authoring shell. Check conceptual fidelity/project mapping and novel transfer reasoning separately from DOM/model tests. No test establishes mastery, universal host behavior or agent compliance. Useful observations include real file-open offline operation, console/network activity where available, desktop/narrow layout, keyboard/focus/touch targets, pause/step/reset/hidden tab, reduced motion, scriptless and print alternatives. Distinguish exercised observations from inferred CSS behavior and unavailable tools. Never weaken browser security or install a driver just to pass.

Temporary-first output; ask open-ended destination after preparation, or reuse an already explicit destination. No delivery while unanswered. Protect exact path/parent/symlink boundaries and preexisting content. Copy to fresh exclusively-created paths, verify complete bytes/assets/relative links, then remove only known disposable invocation staging. A copy failure preserves source and prior files. An uncertain cleanup retains and reports duplicate paths. Ignore/backups/sync/provider context are not secrecy guarantees. Unsupported remote destinations stay unresolved, not silently redirected. A single owner-chosen outside-project final home is supported; no repository lesson retention required.

Optional vault Markdown companion uses a portable relative link and readable summary. HTML storage and normal-browser interaction are qualified separately from actual Obsidian desktop/mobile execution; no forced plugin/settings changes. Native vault note views can restrict scripts. Report the tested route and actual gaps.
